# База знаний RentCRM

## 1. Зарубежные конкуренты и функциональные паттерны

### Buildium

Источник: https://www.buildium.com/features/

Ключевые функции:

1. Property accounting.
2. Online rent collection.
3. Maintenance requests and work orders.
4. Resident center.
5. Rental listing syndication.
6. Tenant screening.
7. Property management website.
8. Online leasing.
9. Marketplace/integrations.
10. Open API.
11. Property owner portal.
12. Business performance reports.

Вывод для RentCRM: даже малый продукт должен иметь не только карточки объектов, но и деньги, объявления, лиды, расходы, уведомления, отчеты и оплату.

### TurboTenant

Источник: https://www.turbotenant.com/features/

Ключевые функции:

1. Rental advertising.
2. Listing syndication.
3. Pre-screeners.
4. Lead management.
5. Showing scheduling.
6. Rental applications.
7. Tenant screening.
8. Maintenance requests.
9. In-app messaging.
10. Lease agreements.
11. E-sign.
12. Online condition reports.
13. Collect rent.
14. AutoPay.
15. Custom late fees.
16. Expense tracking.

Вывод для RentCRM: для РФ MVP стоит усиливать не enterprise-бухгалтерию, а простые операционные сценарии: объявление, лид, платеж, расход, уведомление, договор.

### AppFolio

Источники:

1. https://www.appfolio.com/property-manager/features
2. https://www.techradar.com/best/best-property-management-software

Ключевые функции:

1. Business metrics.
2. Maintenance tracking.
3. Communication with renters, owners and vendors.
4. Owner portal.
5. Online rental applications.
6. Tenant screening.
7. Vacancy advertising.
8. Online rent collection.
9. Mobile inspections.

Вывод для RentCRM: после MVP нужны кабинет арендатора, кабинет собственника для управляющих, мобильные inspections/checklists и финансовые отчеты.

### TenantCloud

Источник: https://www.tenantcloud.com/features

Типовые функции рынка:

1. Tenant portal.
2. Online rent payments.
3. Maintenance management.
4. Accounting and reporting.
5. Listings.
6. Lease management.

Позиционирование относительно RentCRM: не прямой конкурент на РФ-рынке. Сильный бесплатный старт и большой лимит юнитов создают ожидание у пользователей, но продукт не локализован под РФ: нет российских платежей, РФ-договоров, 152-ФЗ-процессов, рублевой отчетности и локальных каналов уведомлений.

### Baselane

Пользовательская вводная:

1. Цена: бесплатно, Core около $20/мес.
2. Фичи: интегрированный банкинг, автобухгалтерия, сбор аренды, tenant screening.
3. Оценка: сильный indirect-конкурент, но не для РФ.

Что важно для RentCRM:

1. Бесплатный план может быть мощным, если продукт монетизируется через платежи/банкинг/финансовые сервисы.
2. Автоматическая категоризация доходов и расходов сильно повышает ценность.
3. Сбор аренды и финансовый учет лучше воспринимаются как единый сценарий, а не как разные модули.

Почему не прямой конкурент в РФ:

1. Нет российских платежных методов.
2. Нет валютного контроля и учета для РФ.
3. Нет локальных договоров и требований 152-ФЗ.
4. Нет интеграций с российскими банками и СБП.

Идеи для RentCRM:

1. Добавить импорт банковских выписок CSV/XLSX.
2. Автоматически сопоставлять платежи арендаторов с начислениями.
3. Добавить категории расходов и простую автобухгалтерию.
4. В будущем рассмотреть интеграции с российскими банками для ИП/ООО.

### Stessa

Пользовательская вводная:

1. Цена: бесплатно, Core около $20/мес.
2. Фичи: трекинг доходов/расходов, отчеты для налогов.
3. Оценка: финансовый инструмент, не CRM, но пересекается по учету.

Что важно для RentCRM:

1. Финансовые отчеты могут быть главным retention-драйвером.
2. Нужны отчеты по объектам: доход, расход, чистый доход, просрочки, окупаемость.
3. Для РФ нужно делать не "налоговую декларацию", а безопасные выгрузки и сводки для бухгалтера/самозанятого/ИП.

Идеи для RentCRM:

1. P&L по объекту.
2. Отчет по просрочкам.
3. Отчет по расходам.
4. Экспорт в Excel.
5. Отдельная страница "Финансы".

### Hemlane

Пользовательская вводная:

1. Цена: бесплатно для 1 объекта, далее около $20-50/мес.
2. Фичи: listing syndication, tenant screening, accounting, ремонты.
3. Оценка: близко к MVP RentCRM, но только США.

Что важно для RentCRM:

1. Listing + lead + screening + lease + payment образуют цельную воронку аренды.
2. Maintenance должен быть не просто списком заявок, а операционным процессом с подрядчиками, сроками и стоимостью.
3. Бесплатный лимит в 1-3 объекта нормален, если дальше тарифы понятны.

Почему не прямой конкурент в РФ:

1. Нет Авито/Циан/Домклик/Яндекс Недвижимости.
2. Нет РФ-платежей.
3. Нет РФ-договоров.
4. Нет локальной коммуникации через Telegram/SMS/WhatsApp-провайдеров.

Идеи для RentCRM:

1. Добавить источники лидов: Авито, Циан, Домклик, ручной, сайт.
2. Добавить статусы лида.
3. Добавить расписание показов.
4. Добавить подрядчиков по заявкам.
5. Добавить расходы из заявок в финансы автоматически.

## 2.1. Уточненное позиционирование для РФ

Зарубежные продукты не являются прямыми конкурентами для РФ-рынка, но формируют ожидания по качеству продукта. RentCRM должен выигрывать за счет локализации:

1. Российские платежи: ЮKassa, СБП, CloudPayments, Т-Банк, Robokassa.
2. Российские договоры и шаблоны документов.
3. 152-ФЗ и хранение ПДн в РФ.
4. Рублевые тарифы и отчеты.
5. Telegram/SMS/WhatsApp-уведомления через доступные для РФ каналы.
6. Интеграции с Авито, Циан, Домклик, Яндекс Недвижимость.
7. Учет сценариев самозанятых, ИП и малых управляющих компаний.

## 4. Операторы приема оплаты для российского рынка

### ЮKassa

Источник: https://yookassa.ru/developers/api

Плюсы:

1. Один из самых понятных вариантов для РФ.
2. Есть API платежей.
3. Есть webhooks.
4. Есть счета, возвраты, чеки, СБП и готовые SDK.
5. Подходит для ИП/ООО/самозанятых в зависимости от условий подключения.

Рекомендация: основной провайдер для MVP.

Текущий статус в приложении: реализовано создание платежа подписки через API ЮKassa.

### CloudPayments

Источник: https://developers.cloudpayments.ru/

Плюсы:

1. Виджет оплаты.
2. API.
3. Рекуррентные платежи.
4. СБП, T-Pay, SberPay, MIR Pay.
5. Уведомления/callbacks.

Рекомендация: хороший вариант для подписочной модели, особенно если нужен рекарринг.

Текущий статус в приложении: провайдер добавлен в настройки, checkout не реализован.

### Т-Банк Касса

Источник: https://developer.tbank.ru/eacq/intro/developer/intro

Плюсы:

1. Интернет-эквайринг.
2. T-Pay.
3. API.
4. Хорошая экосистема для ИП/ООО.

Рекомендация: рассмотреть как второй production-провайдер после ЮKassa.

### Robokassa

Источник: https://docs.robokassa.ru/

Плюсы:

1. Агрегатор платежных методов.
2. Карты, СБП, pay-методы.
3. Поддержка требований 54-ФЗ.

Рекомендация: вариант для быстрого старта с большим набором способов оплаты.

Текущий статус в приложении: провайдер добавлен в настройки, checkout не реализован.

## 5. Персональные данные РФ

Основные источники:

1. Форма уведомления Роскомнадзора: https://pd.rkn.gov.ru/operators-registry/notification/form/
2. Telegram Bot API: https://core.telegram.org/bots/api
3. SMS.RU API: https://sms.ru/api/send

### Какие персональные данные хранит RentCRM

1. Данные пользователей SaaS:
   - email;
   - ФИО;
   - пароль в виде hash.
2. Данные арендаторов:
   - ФИО;
   - телефон;
   - email;
   - ИНН;
   - маскированные паспортные данные;
   - Telegram chat_id;
   - WhatsApp/телефон;
   - история платежей и заявок.
3. Данные объектов:
   - адрес;
   - кадастровый номер;
   - документы и ссылки на файлы.

### Что нужно сделать до промышленного запуска

1. Определить оператора персональных данных: ИП/ООО, которое владеет SaaS.
2. Подать уведомление в Роскомнадзор, если нет применимого исключения.
3. Разместить:
   - политику обработки персональных данных;
   - пользовательское соглашение;
   - оферту;
   - согласие на обработку персональных данных;
   - согласие на получение уведомлений.
4. Хранить первичные базы данных граждан РФ на территории РФ.
5. Заключить договоры с обработчиками:
   - хостинг;
   - SMS-провайдер;
   - платежный провайдер;
   - email-провайдер;
   - облачное файловое хранилище.
6. Описать цели обработки:
   - предоставление SaaS;
   - учет объектов и арендаторов;
   - отправка уведомлений;
   - прием оплаты;
   - техническая поддержка.
7. Реализовать права субъекта:
   - запрос данных;
   - исправление данных;
   - удаление данных;
   - отзыв согласия;
   - отключение уведомлений.
8. Ввести организационные меры:
   - приказ о назначении ответственного за ПДн;
   - модель угроз;
   - перечень ИСПДн;
   - регламент доступа;
   - журнал инцидентов;
   - регламент резервного копирования;
   - регламент удаления данных.
9. Технические меры:
   - HTTPS;
   - backup;
   - audit log;
   - role-based access;
   - минимизация персональных данных;
   - шифрование секретов;
   - ограничение доступа к production БД;
   - хранение токенов провайдеров в secrets/env, а не в открытом виде.

### Важное замечание

Этот документ не заменяет юридическую экспертизу. Перед production запуском надо показать схему обработки ПДн юристу по 152-ФЗ и специалисту по информационной безопасности.

## 6. Production checklist

### Инфраструктура

1. Домен.
2. HTTPS.
3. Российский VPS/облако для базы ПДн.
4. Postgres backup каждый день.
5. Проверка восстановления backup.
6. Мониторинг доступности.
7. Логи backend/frontend/nginx.
8. Rate limiting на auth и уведомления.
9. Docker healthchecks.
10. CI/CD.

1. Сильный `APP_JWT_SECRET`.
2. Секреты провайдеров в env/secrets.
3. Запрет логирования токенов, паролей, паспортных данных.
4. RBAC.
5. Audit log.
6. Ограничение CORS.
7. Защита от brute force.

5. Реализовать продление подписки и дату окончания paid-периода.
6. Реализовать grace period.
7. Реализовать закрывающие документы/чеки с учетом 54-ФЗ.

### Продукт

5. Импорт/экспорт Excel.
6. Генерация договоров из шаблонов.
7. Кабинет арендатора или публичная форма заявок на ремонт.
8. Админка оператора SaaS.
